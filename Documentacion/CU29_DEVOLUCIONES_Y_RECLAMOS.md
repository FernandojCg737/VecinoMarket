## Flujo de VecinoMarket

1. El comprador abre un reclamo desde un pedido propio entregado y pagado. Selecciona el motivo, describe lo ocurrido y adjunta una foto JPG, PNG o WebP de hasta 5 MB. Cada pedido admite un reclamo. Un rechazo puede escalarse dentro del mismo expediente.
2. La empresa o un empleado activo con permiso `gestionar_pedidos` revisa los reclamos de su tenant y escribe una respuesta al aprobar o rechazar. El Admin de soporte consulta todas las solicitudes. El SuperAdmin consulta todas y puede mediar en los casos pendientes o escalados.
3. La aprobación autoriza el reembolso. Para PayPal se usa el identificador de captura y una clave idempotente por intento. Los pagos QR y otros medios manuales requieren registrar la referencia de una transferencia ya realizada. Mientras la confirmación está pendiente, el reclamo conserva el estado de seguimiento.
4. Cuando se confirma el reembolso, se devuelve stock por artículo a su sucursal, el pedido pasa a `DEVUELTO` y se actualiza el pago. Si el checkout agrupaba varias empresas, se devuelve solo el subtotal del pedido reclamado. El pago y la orden permanecen en `REEMBOLSO_PARCIAL` hasta que se reintegre el monto completo.
5. La operación registra la transición en la bitácora y notifica al comprador. La creación también avisa al dueño de la empresa. La foto se sirve desde un endpoint autenticado, acotado al comprador, al tenant autorizado y al personal de plataforma.

El formulario de decisión pide resolver explícitamente la sucursal de artículos históricos cuyo origen es ambiguo. Para pedidos nuevos, el checkout conserva la sucursal exacta por ítem. En Docker las fotos se guardan en un volumen privado independiente de `/media/`. En producción, con Cloudinary configurado, se usa el tipo de entrega autenticado y Django controla la lectura. [Cloudinary](https://cloudinary.com/documentation/control_access_to_media) · [PayPal reembolsos](https://developer.paypal.com/api/payments/v2/captures-refund) · [PayPal idempotencia](https://developer.paypal.com/api/rest/requests/)

### Dónde se usa

- Web de comprador: `/mis-compras` → **Solicitar devolución** o **Ver reclamo**. El historial está en `/mis-reclamos`.
- Web de gestión: **Cuenta → Reclamos de devolución**. Las acciones se calculan en la API por rol, tenant y estado.
- Flutter: **Perfil → Mis reclamos** para el comprador, **Perfil → Reclamos de devolución** para gestión, y **Mis compras** para abrir un reclamo desde un pedido. Las notificaciones del CU29 abren el detalle autenticado.
- API: `GET /api/pedidos/reclamos/`, `POST /api/pedidos/reclamos/crear/`, y recursos de detalle, foto y acción bajo `/api/pedidos/reclamos/{id}/`.

Las referencias PayPal se leen de la captura guardada por el checkout nuevo. Para pagos históricos, se intenta recuperar la captura desde el ID de orden existente. Si la referencia histórica no identifica una captura accesible, el caso queda pendiente de conciliación. La devolución financiera no reemplaza el control físico de recepción que realice la empresa.

En Docker, PayPal Sandbox acepta reembolsos únicamente para checkouts de esa instalación. La aplicación comprueba una referencia generada con su clave local en la orden del proveedor. Los pagos PayPal importados de producción pueden consultarse en el historial. Para ensayar un reembolso de extremo a extremo, se crea primero una compra nueva en Sandbox desde la misma instalación.

Para probar Flutter en un emulador Android con el Docker local, usa una compilación de depuración con `--dart-define=API_URL=http://10.0.2.2:8001/api/`. El manifiesto de depuración permite HTTP y el Compose local admite el host del emulador. La configuración normal de la app sigue usando la API publicada por defecto. [Red del emulador Android](https://developer.android.com/studio/run/emulator-networking-address)

La aprobación de PayPal puede dejar el caso pendiente si la pasarela aún procesa la solicitud o si la conexión se interrumpe. El personal autorizado usa **Verificar reembolso en PayPal** para consultar la referencia conocida o recuperar el resultado del mismo intento. Si ese intento quedó sin referencia y venció su plazo local de reintento, SuperAdmin puede conciliar un identificador de reembolso cuyo importe, captura y referencia externa coincidan con el expediente. [Referencia de reembolso de PayPal](https://developer.paypal.com/serversdk/python/api-endpoints/payments/refund-captured-payment)
